Redesigning Spotify's Dropdown Menu

This case study showcases the analysis and redesign of dropdown components in applications like GCal, Slack, and Spotify. I created an accessible and user-friendly version of Spotify's dropdown based on user experience insights.

Why Dropdowns Matter

Dropdowns are essential in interfaces but often overlooked—until they fail. This analysis looks into dropdown design in GCal, Slack, and Spotify to redesign one by incorporating the positives of the others.

Complete Analysis Overview

GCal offers accessibility and keyboard navigation. Slack excels in visual feedback but lacks tab access. Spotify supports keyboard navigation and active indicators, but its dropdown closes after each action.

Visual Walkthrough

Spotify Workflow

While effective for experienced users, Spotify’s dropdown closes after every action, limiting discoverability for new users.

Keyboard users face similar issues. Additionally, the screen reader skips the first option.

Redesign of Workflow

My redesign allows users to interact repeatedly without dropdown collapse. Options show descriptive hover info.

Hover text is persistent, and options can be reselected. Dropdown clarity is improved with icons and ARIA labels.

Final Design

The final dropdown remains open on interaction, includes arrow icons for binary states, and is fully screen reader accessible.

Reflection on Accessibility & Mismatches

Many dropdowns ignore screen reader dynamics or rely too heavily on mouse interaction. This project prioritizes inclusive design by improving ARIA labels, keyboard navigation, and usability without compromising visual clarity.

Conclusion

Designing a great dropdown means balancing clarity, accessibility, and usability. This project helped me deeply understand how minor interface changes can dramatically affect the user experience. I'm confident this new version improves navigation for all users.
